# ESP32-C3 桌面气象雷达 — 计划文档

## 1. 目标

在 **ESP32-C3 Super Mini + GC9A01 1.28″ 圆屏（240×240）** 上实现端上自洽的气象雷达摆件：

- 算力全部在设备端（下载、合成、缓存、播放）
- 显示：底图 + 开源气象雷达叠图
- 交互：单键（BOOT）+ SoftAP / 网页配置（可扫码）

参考实现：

| 项目 | 用途 |
|------|------|
| [MatixYo/ESP32-Plane-Radar](https://github.com/MatixYo/ESP32-Plane-Radar) | 配网、按键、圆屏 UI、PlatformIO 工程结构 |
| 本仓库 `DesktopRadar/` | RainViewer / 高德底图、墨卡托裁切、图层逻辑（树莓派 Python） |

本仓库（`esp32c3`）为固件落点；不移植树莓派上的多图层（卫星、短临、ADSB 等）。

## 2. 硬件

| 部件 | 说明 |
|------|------|
| MCU | ESP32-C3 Super Mini（约 320–400KB SRAM，无 PSRAM，常见 4MB Flash） |
| 屏 | GC9A01，240×240，SPI |
| 用户键 | **BOOT（GPIO9）**：短按切缩放已实现；启动窗口内跳过配网（规划）；中长按 / 超长按骨架预留 |
| RESET | 仅硬件复位；复位后进入 SoftAP 配置窗口（规划，见 §6.1），**不作**按住时长手势 |

引脚（`include/config.h`）：

| 屏脚 | GPIO |
|------|------|
| RST | 0 |
| CS | 1 |
| DC | 2 |
| MOSI (SDA) | 3 |
| SCLK (SCL) | 4 |
| BLK | 无（常亮） |

## 3. 功能范围

### 3.1 做

- 按缩放档缓存底图（首次加载后该档不再重复拉取）
- 定时拉取雷达历史帧，叠到底图，预渲染为成品帧写入 Flash
- 本地以 **5–10 fps** 轮播约十几张历史雷达图
- SoftAP + Web 配置：WiFi、经纬度、主/备用数据源 URL 等
- **上电 / RST 先进配置门户**；启动窗口内 BOOT 或超时跳过（NVS / 默认）
- 设置屏：**仅 URL 二维码** + 文字热点名 / Web 管理地址；连热点一律手动（系统 WiFi 列表）
- 单键：短按切缩放、中长按动画；运行中超长按可再次进设置（可选）

### 3.2 不做

- FY-4B 卫星、NMC 短临、ADSB 飞机雷达
- 任意连续捏合缩放（仅 3～5 档预设）
- **在播放循环中现解 PNG / 现叠瓦片 / 现拉 HTTPS**（实测不可行，见 §4.5）
- 一次持有 768×768 或整张 256×256 RGBA 于 RAM

## 4. 数据显示架构

### 4.1 流水线

```
首次 / 换位置 / 换缩放档
  → 下载底图瓦片 → 裁成 240×240 → 写入 Flash（按档位）
  → 拉雷达历史帧 → alpha 叠到底图 → 存约 12 张 RGB565 成品帧

平时显示
  → 从 Flash 读成品帧 → SPI 刷屏（5–10 fps 动画）

每 ~15 分钟（可配置）
  → 仅更新雷达 → 叠到已缓存底图 → 覆盖动画帧缓存
```

### 4.2 内存策略

| 策略 | 说明 |
|------|------|
| 屏缓冲 | 播放时一次一块 240×240 RGB565（≈112KB）；静帧 MVP 可直绘 LCD 以省堆 |
| 底图 | 每缩放档一份成品，存 Flash |
| 动画帧 | 约 12 × 112KB ≈ 1.3MB，存 Flash；RAM 中一次只加载当前帧 |
| 瓦片 | **串行** HTTPS；PNG 整包解码（压缩后通常 &lt;40KB）；禁止 768 大画布 |
| WiFi / TLS | 与大块分配错开；勿与 112KB 帧缓冲 + pngle(~45KB) 同时堆分配 |

实测可用堆（已连 WiFi、无大帧缓冲）：自由堆约 **220KB**，最大连续块约 **150–200KB**。  
`pngle` 结构体约 **45KB**（含 32KB lz 窗）；与 112KB sprite **无法同时从堆成功分配**（需静态缓冲、直绘 LCD，或 Flash 中转后再解）。

### 4.3 缩放档位

- 预设 **3～5 档**（例如对应不同 Web Mercator zoom）
- 每档独立底图缓存；无缓存时该档首次切换会触发一次底图下载（可显示进度）
- RainViewer 免费档雷达瓦片原生约至 **z7**；更高档对 z7 瓦片 **双线性**上采样后写入 RGB565 成品
- **当前固件**：默认 zoom=7；短按 z3–12；LittleFS 存每档 RGB565（含 HUD），命中秒切；空闲铺满全档
- **HUD（烘焙进成品）**：白十字 + 红心点；底栏北京时间 `WWW HH:MM`（帧时间戳，非 NTP 墙钟）
- **造片 FS**：逐张解码贴图并立刻删临时文件；启动/造片前 scrub 残留，避免 2.375MB LittleFS 峰值撑爆导致无法 commit（秒切退化）

### 4.4 动画与时间分辨率

| 项 | 预期 |
|----|------|
| 历史窗口 | 约 2 小时（随数据源而定） |
| 源帧间隔 | 约 10 分钟一帧 → 约十几张独立雷达图 |
| 播放帧率 | **5–10 fps**（本地回放，非雷达采样率） |
| 雷达刷新 | 默认约 **15 分钟** 全量重拉并重渲动画集 |

### 4.5 实测性能与结论（2026-08-01）

静帧 MVP（底图 4 瓦片 + 雷达 4 瓦片 + JSON，串行 HTTPS）：

| 阶段 | 量级 |
|------|------|
| 整帧出图（含 WiFi） | 约 **20–25 s** |
| 瓶颈 | **HTTPS/TLS ≫ PNG 解码 ≫ SPI 刷屏** |
| SPI 刷 240×240 | &lt;50 ms，可忽略 |

对动图的含义：

- **不可行**：播放循环内「每帧现下现解」——12 帧 × 每帧约 4 张雷达瓦片 ≈ 分钟级，无法 5–10 fps  
- **可行**：预渲 RGB565 进 Flash，播放仅 **Flash → SPI**；C3 可稳定 5–10 fps  
- 造片成本（约每 15 分钟）：可接受，需进度 UI；底图必须按档强缓存

## 5. 数据源

### 5.1 雷达

- 默认：[RainViewer](https://www.rainviewer.com/) Weather Maps API（`weather-maps.json` + PNG 瓦片）
- 瓦片形态：`{host}{path}/256/{z}/{x}/{y}/4/1_1.png`
- 免费档能力可能变更；固件将 **API 根 URL / 模板做成可配置**（Web 阶段）

### 5.2 底图

- 默认：高德 `webrd0{1-4}.is.autonavi.com` 矢量路网瓦片（`style=8`，需 `Referer: https://www.amap.com/`）
- 直链存在失效或限流风险；依赖 **Flash 强缓存** + 可替换底图源配置

### 5.3 容灾原则

- 假定第三方源会改协议或短暂不可用
- 雷达更新失败时继续显示上一套动画/静帧，并提示数据过期
- 用户可通过 Web 页按说明更换数据源，无需重刷固件（OTA 可作为后续增强）

## 6. 配网与 Web 设置

### 6.1 启动先进配置（RST 间接入口）

**RST 不能当应用按键**（硬件复位，无手势回调）。采用「每次上电 / RST 后先进入 SoftAP 配置门户」：

```
上电 / 按 RST
  → 开 SoftAP（如 Radar-Setup）+ 屏显「文字说明 + 仅 URL 二维码」
  → 等待用户（建议超时 30–60s）
       ├─ 在门户页保存配置 → 写 NVS → 关 SoftAP → 进正常雷达
       ├─ 短按 BOOT → 跳过门户，用 NVS（无则用编译默认）→ 进正常雷达
       └─ 超时无人操作 → 与按 BOOT 相同，自动继续（摆件友好）
```

效果：

- **按 RST** ≈ 再次进入 Web 配置窗口（重启副作用）
- **按 BOOT**（启动窗口内）=「别配了，按已有/默认跑」
- **15 分钟雷达刷新**在 `loop` 内完成，**不重启**，不会反复进配置

可选增强：运行中超长按 BOOT 可再次进入同一门户（与启动窗口并存）。

技术路线：SoftAP + 嵌入式 Web + NVS；WiFiManager 或自写均可。

**当前固件**：上电/RST 先进 SoftAP（`Radar-Setup`）+ Web（PSK/PEAP + 经纬度）写 NVS；BOOT/60s 可跳过。WiFi 默认仍可在 `config.h` 作回退。

### 6.2 模式对照

| 模式 | 时机 | 行为 |
|------|------|------|
| SoftAP 配置门户 | **每次上电/RST**（主路径）；可选运行中超长按 BOOT | 热点 + `http://192.168.4.1` |
| 跳过配置 | 启动窗口内短按 BOOT，或超时 | 读 NVS → 无则 `config.h` 默认 → STA 连网跑雷达 |
| 局域网配置页（可选） | 已加入家用 WiFi 后 | `http://<IP>`；此时勿再提示连 SoftAP |

### 6.3 可配置项（初版）

- WiFi SSID / 密码
- 雷达中心纬度 / 经度
- 缩放档位默认值
- 雷达刷新间隔
- 主 / 备用雷达 API 根地址（及必要时底图源）
- 「恢复默认数据源」

BOOT 跳过时：**优先 NVS 已保存值**，不要每次清空用户改过的参数。

### 6.4 设置屏展示（兼容优先）

**原则：不依赖扫「WiFi 入网码」。** 各品牌手机对 `WIFI:...` 二维码支持不一（有的只填表、有的要确认、有的直接失败），容易卡在「以为连上了其实没连」。连热点一律走系统 WiFi 列表手动选择，流程最稳。

屏上只展示这些（240 圆屏信息要少而硬）：

| 元素 | 内容示例 | 作用 |
|------|----------|------|
| 文字：热点名 | `WiFi: Radar-Setup` | 让用户去手机设置里对准这个名字连 |
| 文字：管理地址 | `http://192.168.4.1` | 连上后可手打进浏览器（不依赖扫码） |
| **仅一个 URL 二维码** | 内容为上述管理地址 | 连上热点后扫码打开网页，少打字 |
| 一行提示 | `先连 WiFi，再扫码/打开网址` | 避免只扫码却进不了页 |

**不做：**

- 不显示 WiFi 入网二维码（`WIFI:T:...;S:...;P:...;;`）
- 不暗示「扫一下就能连上热点」

正确用户路径（固定两步）：

1. 手机「设置 → WLAN」手动选屏上写的热点名（如 `Radar-Setup`）并连接  
2. 浏览器打开屏上写的 URL，**或**扫屏上的 URL 码  

说明：扫 URL 码 **只会打开网页**，**不会**帮你连热点；没连上 SoftAP 时扫码会失败或打不开板子。

已在家用局域网、仅改参数时：文字显示当前设备 IP/主机名 + 同一 URL 二维码即可，勿再提示连 SoftAP。

## 7. 按键交互

### 7.1 RST

- **仅硬件复位** → 触发 §6.1 启动配置窗口  
- 不做按住时长检测  

### 7.2 BOOT（GPIO9）

| 场景 | 行为 |
|------|------|
| **启动配置窗口内**短按 | 跳过 SoftAP，按 NVS / 默认继续跑雷达 |
| 正常运行、短按（如 &lt; 0.8s，`BTN_SHORT_MS`） | 循环切换缩放档位；已缓存则秒切（不显示 z 标签） |
| 正常运行、中长按（如 0.8～3s） | 播放 / 停止历史动画 |
| 正常运行、超长按（≥ 10s，可选） | 再次进入 SoftAP 配置门户 |

运行中手势以 **松手时的按住时长** 区分。按住过程可提示：≈1s `松开: 动画`，≈10s `松开: 设置`。

## 10. 风险与缓解

| 风险 | 缓解 |
|------|------|
| C3 内存不足 | 串行瓦片；勿同时堆分配 sprite+pngle+TLS；播放只用 Flash→SPI；底栏字用 `LGFX_Sprite::setBuffer` 复用帧缓冲 |
| LittleFS 写入截断 | 实测存在 http 长度与落盘长度不一致；动画缓存前须验证分区与写读闭环，或改用更稳存储方案 |
| LittleFS 造片峰值撑满 | 成品约 10×115KB；旧流程一次堆齐 raw/alpha 会 `No more free space`；现逐张贴图 + orphan scrub |
| 底图直链失效 | 强缓存 + Web 可换源 |
| 雷达 API 变更 | 可配置 URL + 说明书备用地址 |
| 合成耗时长（~20s/静帧） | 进度提示；动画与合成分离；底图缓存 |
| 单键误触 | 时长分段 + 按住提示文案 |
| RGB565 底图偏绿 | 压暗与 alpha 混合在 8-bit 域计算后再量化 |
